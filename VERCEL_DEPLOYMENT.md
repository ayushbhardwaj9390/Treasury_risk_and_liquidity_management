# Application deployment

The repository root now contains a Next.js deployment configuration, a locked pnpm workspace, and the frontend application. Vercel can build from the repository root with the committed vercel.json. A frontend-only root is also supported by frontend/vercel.json.

Without API_BASE_URL or NEXT_PUBLIC_API_BASE_URL, Vercel serves the explicitly labelled recorded synthetic demonstration. The committed snapshot was generated by the deterministic engines through scripts/smoke_application.py. It supports the analysis library without contacting a developer computer. These recorded reports do not perform fresh calculations. The separate Automatic updates workspace calculates fresh positions from a fixed fictional feed for a single-country business or an MNC; it does not use customer data or update authoritative company records. Neither demonstration executes payments, approvals, trades or live AI calls. See [automatic dummy updates](docs/AUTOMATIC_DUMMY_UPDATES.md).

To connect a hosted backend, set API_BASE_URL to its HTTPS URL in Vercel and redeploy. Backend authentication and production controls still apply. Configured backend failures are surfaced and never silently replaced with recorded data. Do not put secrets in NEXT_PUBLIC variables.

Production remains BLOCKED_EXTERNAL_EVIDENCE until real integration evidence, validation, operational evidence, and required role sign-offs satisfy the existing gates. The energy pilot is fictional and is not certified by Shell or any bank, ERP provider, tax authority, or legal adviser.

Historical initial deployment verification: 176 backend regressions, 80 application HTTP checks, seven proxy tests, TypeScript checks and the root production build passed for that release. Later releases add workspaces and checks; see [current project status](PROJECT_STATUS.md) and the release-specific verification documents for current evidence. The interface includes independent panel error handling, a searchable analysis library, and responsive navigation and tables.

The connected Vercel project must track main. If an older project setting uses a nonexistent root directory, reset Root Directory to the repository root and redeploy the latest main commit. Check Vercel's deployment build log and domain assignment if a successful upload still leaves the previous 404 visible.
